# סוכן סיכום שבועי למאמני ריצה

מנוע שמקבל את האימונים של מתאמן ומחזיר סיכום שבועי למאמן, בפורמט שמוכן לוואטסאפ:
נפח, חלוקת עצימות לפי זונים, פירוק אימוני מפתח, עומס (TSS / CTL / ATL / TSB), תחושות והתראות.

מה יש כבר:
- **מנוע הניתוח**: סיכום שבועי לכל מתאמן.
- **שאלון מתאמן**: המאמן ממלא פעם אחת לכל מתאמן, והמנוע מתאים את עצמו לפי התשובות.
- **התראה מיידית על אימון חריג**.
- **בוט וואטסאפ**: שולח למאמן את הסיכומים וההתראות, ועונה לפקודות.

מה עוד חסר:
- חיבור ל-TrainingPeaks או לגארמין. עד אז הנתונים מגיעים מקבצי JSON או FIT.
- הפסקה שכותב Claude.

## הרצה

```bash
cd coach-agent
pip install -r requirements.txt
python examples/make_demo.py                                   # נתוני דמו של 2 מתאמנים
python -m coach_agent report examples/athletes/*.json --week 2026-11-15
python -m coach_agent check examples/athletes/michal.json --from 2026-11-15   # אימונים חריגים
```

בלי `--week` הדוח מתייחס לשבוע האחרון שהסתיים, לפי יום תחילת השבוע של כל מתאמן.

דוגמה לפלט: [`examples/demo_report.txt`](examples/demo_report.txt).

זונים מתוצאת מרוץ:

```bash
python -m coach_agent zones --race 10 41:40
python -m coach_agent zones --race 5 20:00 --hr 178        # 5 ק"מ עם דופק ממוצע -> גם דופק סף
```

קבצי FIT מגארמין (Garmin Connect ← אימון ← ⚙ ← Export Original):

```bash
python -m coach_agent report athlete.json --fit-dir ./fits --week 2026-11-15
```

אפשרויות: `--prefer pace|hr|max` ו-`--week-start <יום>` דורסים את מה שבשאלון. `--json` מוציא את הנתונים כ-JSON.

## השיטה

**קצב סף** = הקצב שאפשר להחזיק שעה (ג'ו פרייל). מתוצאת 5 או 10 ק"מ מחושב לפי נוסחת ריגל
(T2 = T1 × (D2/D1)^1.06) המרחק שהמתאמן היה רץ ב-60 דקות. כך 5 ק"מ נופל ב-Z5b, 10 ק"מ ב-Z5a,
חצי מרתון ב-Z4 ומרתון ב-Z3.

- התוצאה העדכנית ביותר קובעת (עד 180 יום אחורה). 10 ק"מ מנצח 5 ק"מ חדש יותר אם הפער עד 30 יום.
- **דופק סף**: דופק ממוצע ב-5 ק"מ ÷ 1.05 בתחרות, ÷ 1.01 במבחן באימון.
- המאמן יכול תמיד להזין ידנית קצב סף ודופק סף.

| זון | קצב (% מקצב הסף) | דופק (% מדופק הסף) |
|---|---|---|
| Z1 | איטי מ-129% | עד 85% |
| Z2 | 114–129% | 86–90% |
| Z3 | 106–113% | 91–95% |
| Z4 | 100–105% | 96–99% |
| Z5a | 96.5–100% | 100–101% |
| Z5b | 90–96.5% | 102–105% |
| Z5c | מהיר מ-90% | 106%+ |

**פירוק אימון**: לאפים רצופים מאותו סוג (קל / בינוני / עצים) מתאחדים. טמפו שנרשם כ-8 לאפים
של ק"מ יוצא "8 ק"מ Z4 נמוך→גבוה", פארטלק שומר כל קטע, וחזרות שוות מתקפלות לשורה אחת ("6×1 ק"מ Z5a").
סוג האימון מזוהה אוטומטית: טמפו, אינטרוולים נרחב (Z5a), אינטרוולים עצים (Z5b), חזרות (Z5c), פארטלק, עליות, ארוכה, קלה, התאוששות.

**עומס**: rTSS = שעות × IF² × 100. לכל לאפ בנפרד, או מזרם שנייה-שנייה כשיש. בלי קצב
מחושב לפי דופק, ובלי דופק לפי RPE. CTL על פני 42 יום, ATL על פני 7 ימים, TSB = CTL − ATL.

**התראות** (כל הספים בראש `coach_agent/week.py`):
- כאב, פציעה או מחלה בהערת המתאמן (🔴), עייפות (🟠)
- קפיצה של יותר מ-15% בנפח מעל ממוצע 4 שבועות
- עלייה של יותר מ-7 נקודות CTL בשבוע, או TSB מתחת ל-‎-30
- יותר מ-30% מזמן הריצה ב-Z4 ומעלה, או יותר מ-15% ב-Z3 ("אזור אפור")
- שני אימוני איכות בלי מספיק התאוששות: 36 שעות ל-Z4/Z5a, 48 ל-Z5b, 72 ל-Z5c
- ריצה קלה עם RPE 7 ומעלה
- דה-קאפלינג של יותר מ-5% בריצה ארוכה
- אימון מתוכנן שלא בוצע
- סף שמבוסס על תוצאה ישנה מ-90 יום

ויש גם נקודות חיוביות (🟢): שיפור ביעילות האירובית (אותו קצב בדופק נמוך יותר), ריצה ארוכה יציבה, רעננות.

## שאלון מתאמן

המאמן ממלא שאלון לכל מתאמן. אפשר בטרמינל עם `python -m coach_agent intake athletes/yossi.json`, ואותן שאלות יעבדו גם בוואטסאפ. השאלון שומר את התשובות בקובץ של המתאמן, ומה שהמנוע עושה עם התשובות:

| תשובה | מה המנוע עושה איתה |
|---|---|
| **יום תחילת שבוע** (כל יום: ראשון, שני, שבת...) | השבוע של כל מתאמן נחתך לפי היום שלו, והסיכום נשלח בבוקר שאחרי סוף השבוע שלו |
| לפי מה קובעים זון (קצב / דופק / הקשה מביניהם) | מתאמן שטח יכול לעבוד לפי דופק |
| תחרות מטרה, תאריך, זמן יעד | שורת "עוד X שבועות" בראש הדוח, זיהוי טייפר, והתראה אם הנפח לא ירד בטייפר |
| טווח נפח שבועי | התראה מעל המקסימום או מתחת למינימום |
| מקסימום אימוני איכות בשבוע | התראה כשיש יותר |
| עלייה מקסימלית בנפח (%) | מחליף את ברירת המחדל של 15% |
| מחזוריות (3:1 / 2:1 / 4:1) | בדיקת שבוע ההורדה ומספר שבועות העומס |
| התקדמות בריצה הארוכה (ק"מ) | ברירת מחדל 0.5–2.5 |
| עלייה מקסימלית בק"מ עצימים | ברירת מחדל: לא נבדק |
| פציעות: אזורים לשים עליהם עין | כל הערה שמזכירה את האזור עולה כ-🔴, גם בלי המילה "כאב" |
| תוצאת 5/10 ק"מ, קצב סף ודופק סף ידניים | קובעים את הזונים |
| שינה, עומס בחיים, ענפים נוספים, הערות מאמן, מידע רפואי | נשמרים בשביל הפסקה ש-Claude יכתוב |

`python -m coach_agent questionnaire` מדפיס את כל השאלות.

## התראה על אימון חריג

כל אימון חדש נבדק מיד. אם יש בו משהו חריג, המאמן מקבל הודעה בוואטסאפ:

```
*מיכל לוי*, א׳ 15.11, ריצה בינונית (Z3)
תוכנן: ריצה קלה 10 ק"מ
10 ק"מ, 5:20 לק"מ, 53 דק׳, דופק 164, RPE 6
תוכנן עד Z2, בפועל 53 דק׳ ב-Z3
```

מה נבדק:
- זמן מעל הזון המתוכנן: 10 דקות לפחות או 20% מהריצה. אם המאמן לא תכנן את האימון, ריצה רציפה בלי מבנה של אימון איכות נבדקת כריצה קלה, עד Z2.
- קטעים מהירים יותר מהקצבים המתוכננים.
- RPE גבוה ב-2 ומעלה מהמתוכנן, ריצה קלה עם RPE 7 ומעלה, או RPE 9 ומעלה בכל אימון.
- כאב, פציעה, מחלה או עייפות בהערה, ואזכור של אזור פציעה מוכר.
- דופק גבוה ב-2 זונים ומעלה ממה שהקצב מסביר (חום, עליות, עייפות, תחילת מחלה).
- אימון איכות לפני שעבר זמן ההתאוששות מהקודם, או יותר אימוני איכות מהמתוכנן לשבוע.
- ריצה ארוכה שגדלה ביותר מהמותר לעומת השבועות האחרונים.

## מחזוריות: שבועות עומס ושבוע הורדה

בתוך כל מחזור (3:1, 2:1 ...) כל שבוע עומס עולה באותו צעד. שבוע ההורדה יורד מתחת לשבוע הראשון של המחזור באותו צעד. הכלל הזה חל על הנפח, על הריצה הארוכה ועל העצימות:

| | שבוע 1 | שבוע 2 | שבוע 3 | הורדה |
|---|---|---|---|---|
| ריצה ארוכה | 8 | 9 | 10 | **7** (8 פחות 1) |
| נפח | 37 | 39 | 41 | **35** (37 פחות 2) |
| עליות | 6 | 7 | 8 | **5** |

המחזור הבא מתחיל צעד אחד מעל שבוע העומס האחרון.

המנוע מזהה את המחזורים לבד מתוך הנתונים: שבוע שהנפח שלו ירד לעומת השבוע הקודם הוא שבוע הורדה. העצימות נמדדת בדקות ב-Z4 ומעלה.

מה המנוע בודק ומתי:

| מתי | מה | רמה |
|---|---|---|
| שבוע הורדה | נשאר מעל "שבוע ראשון פחות צעד" | 🟠 |
| שבוע הורדה | ירד הרבה יותר מזה | 🔵 |
| שבועות עומס | יותר שבועות עומס ברצף ממה שנקבע במחזור | 🟠 |
| שבועות עומס | עלייה גדולה מהצעד של המחזור | 🔵 |

בדוח מופיעה גם שורה כמו "שבוע עומס 2 מתוך 3 במחזור" או "שבוע הורדה (אחרי 3 שבועות עומס)". את המחזור קובעים בשאלון.

התכנון העונתי לדוגמה (37 שבועות לקראת מרתון) עובר את הבדיקה כמעט בלי הערות. יוצא רק שבוע 34, שבו ההורדה שלפני תקופת השיא עמוקה מהכלל.

## התקדמות משבוע לשבוע

ההשוואה היא תמיד מול השבוע הכי גבוה מבין 3 השבועות האחרונים. כך שבוע הורדה במחזור 3:1 או 2:1 לא מאפס את ההתקדמות: הארוכה שאחרי שבוע ההורדה נמדדת מול הארוכה של שבוע העומס האחרון.

| מה | ברירת מחדל | בשאלון |
|---|---|---|
| נפח שבועי | עד +15% מעל ממוצע 4 שבועות | "עלייה מקסימלית בנפח (%)" |
| ריצה ארוכה (LSD) | +0.5 עד +2.5 ק"מ. מעל זה 🟠, מתחת זה 🔵 (לא בשבוע הורדה ולא בטייפר) | "התקדמות בריצה הארוכה" |
| נפח עצים (Z4 ומעלה) | לא נבדק עד שהמאמן קובע מספר | "עלייה מקסימלית בק"מ עצימים" |

את כוונת האימון לוקחים מהתכנון: `zone_min` / `zone_max`, `pace_fast` / `pace_slow`, `rpe`. אם אין אותם, המנוע מנחש מהכותרת ("קלה" → Z1–Z2, "טמפו" → Z4–Z5a).

בדיקה ידנית: `python -m coach_agent check athletes/michal.json --from 2026-11-15`

## וואטסאפ

לבוט יש מספר וואטסאפ משלו, והוא שולח למאמן:
- **התראה** על כל אימון חריג, כשהאימון עולה.
- **סיכום שבועי** בבוקר שאחרי סוף השבוע של כל מתאמן, בשעה שהמאמן בחר (`send_hour`). אם יש כמה מתאמנים, הוא שולח קודם הודעת פתיחה עם כולם ואחריה הודעה לכל מתאמן.

המאמן יכול לכתוב לבוט:
- `סיכום`: הסיכום של השבוע האחרון לכל המתאמנים
- `סיכום דני`: רק למתאמן אחד
- `שאלון`: השאלון למתאמן חדש

**חלון 24 השעות של וואטסאפ:** עסק יכול לשלוח הודעה חופשית רק עד 24 שעות אחרי ההודעה האחרונה של המאמן. מחוץ לחלון הבוט שולח תבנית קצרה שאושרה מראש, למשל "הסיכום השבועי של דני ומיכל מוכן, השב/י כדי לקבל אותו". כשהמאמן עונה, כל ההודעות שחיכו נשלחות בבת אחת.

הרצה:

```bash
python -m coach_agent serve --config coaches.json --state state.json --port 8080
```

השרת מקבל את ההודעות מוואטסאפ ושולח כל שעה מה שצריך. בלי משתני סביבה הוא רץ במצב ניסיון: מדפיס את ההודעות למסך ולא שולח.
סבב שליחה ידני: `python -m coach_agent dispatch --config examples/coaches.json --state state.json`.

### הקמת המספר (פעם אחת, אצל Meta)

1. פותחים [Meta Business](https://business.facebook.com) ומאמתים את העסק.
2. ב-[developers.facebook.com](https://developers.facebook.com) יוצרים אפליקציה מסוג Business ומוסיפים לה את המוצר WhatsApp.
3. מוסיפים מספר טלפון. הוא צריך להיות **מספר שלא רשום בוואטסאפ רגיל**, למשל סים חדש או מספר וירטואלי. מגדירים לו שם תצוגה ותמונה.
4. יוצרים System User עם הרשאות `whatsapp_business_messaging` ו-`whatsapp_business_management`, ומפיקים לו טוקן קבוע.
5. מגישים לאישור שתי תבניות בעברית, בקטגוריית Utility:
   - `coach_weekly_summary`: `הסיכום השבועי מוכן: {{1}}. השב/י כאן כדי לקבל אותו.`
   - `coach_workout_alert`: `אימון חריג: {{1}}. השב/י כאן לפירוט.`
6. מגדירים Webhook לכתובת `https://<השרת>/webhook` עם Verify Token לבחירתכם, ונרשמים לשדה `messages`.
7. מגדירים בשרת את משתני הסביבה:
   - `WHATSAPP_TOKEN`
   - `WHATSAPP_PHONE_NUMBER_ID`
   - `WHATSAPP_VERIFY_TOKEN`
   - `WHATSAPP_APP_SECRET` (מ-App Settings → Basic)

השרת חייב לרוץ כל הזמן ולהיות זמין בכתובת HTTPS ציבורית, למשל Render, Railway, Fly.io או VPS קטן.
Meta גובה תשלום קטן על כל שיחה שהעסק פותח (תבנית Utility). הודעות בתוך חלון 24 השעות לא עולות כסף.

## השלבים הבאים

1. **מקור נתונים**: TrainingPeaks API (דורש אישור שותף) או Garmin Connect Developer Program, במקום קבצים.
2. **פסקת מאמן מ-Claude** בכל סיכום, ושאלות חופשיות בוואטסאפ, למשל "למה ה-TSS של דני קפץ?".
3. **מילוי השאלון בשיחה** בוואטסאפ, שאלה אחרי שאלה.
4. **ריבוי מאמנים**: מאמנים, מתאמנים וספים ב-Supabase במקום בקבצים.
