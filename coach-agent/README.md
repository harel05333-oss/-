# סוכן למאמני ריצה – תיקייה לכל מתאמן

הסוכן מושך את האימונים של כל מתאמן מ-TrainingPeaks, מסדר אותם **לפי השבוע של המתאמן** (ולא לפי שני–ראשון הקבוע של TrainingPeaks), ובונה לכל מתאמן תיקייה עם:

- **נפח שבועי** – ק"מ ודקות, כמה ריצות, כמה קלות וכמה איכות.
- **חלוקת עצימות** – כמה ק"מ ודקות היו קלים (אזורים 1–2, או תחושת מאמץ 1–4) וכמה עצימים, ואחוז הזמן הקל מול היעד שהמאמן קבע (למשל 80/20).
- **דקות לכל רמת מאמץ** – המאמן קובע לכל מתאמן קצב לכל תחושת מאמץ (למשל 6 = 4:20, 7 = 4:10, 8 = 4:00), והסוכן מחשב כמה דקות וק"מ המתאמן רץ בכל רמה, ומשווה לתוכנית ("20 דק' בתחושת מאמץ 6-8" → בוצעו 18).
- **עמידה בתוכנית** – לכל אימון: בוצע / חלקי / מעל המתוכנן / לא בוצע / לא מתוכנן, ואחוז ביצוע שבועי.
- **עמידה באזורים** – ריצה קלה שנעשתה חזק מדי, או אימון איכות בלי מספיק עצימות.
- **מה טוב ומה לשפר** – הערות קצרות לכל שבוע, ומבט-על לכל המתאמנים של המאמן.

## מבנה התיקיות שנוצר

```
output/
└── <מאמן>/
    ├── overview.md            ← טבלה אחת: השבוע האחרון של כל מתאמן
    └── <מתאמן>/
        ├── report.md          ← דוח מלא בעברית, שבוע אחר שבוע
        ├── weekly_summary.csv ← שורה לכל שבוע (נפתח באקסל)
        ├── workouts.csv       ← כל אימון: מתוכנן מול בוצע, קל/עצים, הערות
        ├── summary.json       ← אותם נתונים לכלים אחרים
        └── coach_notes.md     ← (עם --ai) הערות אימון שכתב Claude
```

דוגמה מלאה עם נתונים מומצאים: [`examples/output/harel/overview.md`](examples/output/harel/overview.md). דנה ויוסי נמדדים לפי אזורי דופק, ונועה לפי תחושת מאמץ מקצב ([הדוח שלה](examples/output/harel/noa/report.md)).

## הגדרת מאמנים ומתאמנים

קובץ JSON אחד ([`examples/config.json`](examples/config.json)):

```json
{
  "coaches": [{
    "id": "harel", "name": "הראל",
    "athletes": [
      {"id": "dana", "name": "דנה", "csv": "data/dana.csv", "tp_athlete_id": "123456",
       "week_start": "ראשון", "easy_max_zone": 2, "target_easy_pct": 80, "weekly_km_target": 50}
    ]
  }]
}
```

| שדה | משמעות |
|---|---|
| `week_start` | היום שבו מתחיל השבוע של המתאמן: `ראשון`, `שבת`, `שלישי`… (או באנגלית). ברירת מחדל: שני, כמו ב-TrainingPeaks |
| `easy_max_zone` | עד איזה אזור נחשב "קל" (ברירת מחדל 2) |
| `target_easy_pct` | אחוז הזמן הקל שהמאמן מכוון אליו |
| `weekly_km_target` | יעד ק"מ שבועי (לא חובה) |
| `quality_min_minutes` | כמה דקות מעל האזור הקל הופכות ריצה ל"איכות" (ברירת מחדל 10) |
| `easy_tolerance_min` | כמה דקות מעל האזור הקל מותרות בריצה קלה (ברירת מחדל 5, או 10% מהזמן) |
| `rpe_paces` | קצב לכל תחושת מאמץ, למשל `{"6": "4:20", "7": "4:10", "8": "4:00"}` (דקות:שניות לק"מ) |
| `easy_max_rpe` | עד איזו תחושת מאמץ נחשב "קל" (ברירת מחדל 4, כלומר 1–4) |
| `files_dir` | תיקייה עם קובצי הריצה של המתאמן (`.fit` / `.tcx`), נדרשת לחישוב לפי תחושת מאמץ |
| `csv` / `tp_athlete_id` | מקור הנתונים: קובץ ייצוא, או מזהה המתאמן ב-API |

## הרצה

דורש Python 3.10 ומעלה, בלי חבילות נוספות.

```bash
cd coach-agent
python3 -m coach_agent --config examples/config.json --out output
```

אפשרויות:

- `--from 2026-09-01 --to 2026-11-08` – טווח תאריכים (ברירת מחדל: 8 השבועות האחרונים). תמיד מדווחים שבועות שלמים.
- `--source api` – משיכה ישירה מ-TrainingPeaks (ראו למטה) במקום מקבצי CSV.
- `--zones hr|pace|auto` – לפי אילו אזורים לחשב (דופק, קצב, או אוטומטי: דופק אם יש).
- `--ai` – Claude כותב לכל מתאמן הערות "מה עבד / מה לשפר / מה בשבוע הבא" על בסיס המספרים שחושבו. דורש `pip install anthropic` ומפתח `ANTHROPIC_API_KEY`.

שבוע שעוד לא נגמר מסומן "בתהליך", ולא מקבל אזהרות על נפח או ביצוע חלקי.

## חיבור ל-TrainingPeaks

**היום – ייצוא CSV (עובד מיד):** בחשבון המאמן, לכל מתאמן: Settings → Export Data → *Workout Summary*, בוחרים טווח תאריכים ושומרים את `workouts.csv`. הקובץ כולל את האימון המתוכנן, מה שבוצע, ודקות בכל אזור דופק/קצב – כל מה שהסוכן צריך.

**API ישיר:** ה-API של TrainingPeaks פתוח רק לשותפים מאושרים. צריך להגיש בקשה ל-TrainingPeaks, לקבל אפליקציית OAuth, והמאמן מאשר גישה. אחרי שמקבלים access token:

```bash
export TP_ACCESS_TOKEN=...
python3 -m coach_agent --config config.json --source api
```

את שמות השדות בקוד (`coach_agent/sources/tp_api.py`) כדאי לאמת מול התיעוד שמקבלים מ-TrainingPeaks עם האישור.

## תחושת מאמץ לפי קצב

1. המאמן מגדיר למתאמן `rpe_paces`, למשל:
   ```json
   "rpe_paces": {"4": "5:30", "5": "4:50", "6": "4:20", "7": "4:10", "8": "4:00", "9": "3:45"},
   "easy_max_rpe": 4,
   "files_dir": "data/noa_files"
   ```
2. מייצאים מ-TrainingPeaks את קובצי הריצה עצמם: Settings → Export Data → *Workout Files*, ושמים אותם בתיקייה של המתאמן. הסוכן מתאים כל קובץ לאימון של אותו יום.
3. כל קטע בריצה (קצב מוחלק על 30 שניות, בלי עצירות) משויך לרמת המאמץ שהקצב שלה הכי קרוב. בדוגמה: 4:20 → מאמץ 6, ‏4:12 → מאמץ 7, ‏4:00 → מאמץ 8. קצב איטי משמעותית מהרמה האיטית ביותר שהוגדרה נחשב קל (1–4). אם רוצים שמאמץ 5 ייספר בנפרד, צריך להגדיר לו קצב.
4. בתיאור האימון ב-TrainingPeaks כותבים את הקטעים כרגיל: `20 דק' בתחושת מאמץ 6-8`, `6x3 דק' בתחושת מאמץ 8`, `4x5 min RPE 8`. הסוכן סוכם כמה דקות היו בטווח הזה בפועל, ומסמן אם הגיע לפחות מ-80% מהמתוכנן או אם רץ מהר יותר מהטווח.

ריצה שיש לה קובץ וקצבים מוגדרים נמדדת לפי תחושת מאמץ. אחרת לפי אזורי דופק/קצב מהסיכום, ואם אין גם אותם, לפי כותרת האימון.

## איך הנתונים מחושבים

- **שבוע אישי:** כל אימון משויך לשבוע לפי `week_start` של המתאמן. שבוע ראשון–שבת, שבת–שישי או שלישי–שני – כל מתאמן לפי מה שהמאמן קבע.
- **קל מול עצים:** מתוך הדקות בכל אזור. הק"מ מתחלקים לפי אותו יחס זמן (הערכה, כי הייצוא לא נותן מרחק לכל אזור). ריצה בלי נתוני אזורים מסווגת לפי הכותרת (אינטרוולים, טמפו, עליות… = איכות) ומסומנת.
- **ביצוע:** זמן שבוצע מול זמן מתוכנן (או מרחק, אם אין זמן). 80%–120% = בוצע.
